# 常见问题

## 工具拒绝开始构建

**「构建号不一致：英文 33.0.0.5050，中文 32.2.0.4020」**

两个语言包来自不同的 SOLIDWORKS 构建，不能合并。
它们的资源 ID 指向不同的字符串，合并结果会把毫不相干的标签配成一对。
请重新运行 SOLIDWORKS 安装程序，添加与当前构建匹配的中文包。

**「英文文件夹中没有任何 DLL 能在中文文件夹里找到同名文件」**

有一个路径指的不是语言包。语言包文件夹里有 `sldresu.dll`，共约 270 个文件；
它的上一级 `lang` 才是语言目录。

**「读不到 sldresu.dll」**

该文件夹不是语言包，或文件无法读取。构建会带着警告继续，但请先核对路径。

## 构建中途失败

**「拒绝访问」或权限错误**

输出文件夹不可写，或文件正被 SOLIDWORKS 占用。
请选择 `Program Files` 之外的输出文件夹，例如 `D:\bilingual`。

**个别文件被报告为跳过**

没有中文对应文件、以及没有任何可合并内容的文件，属于正常情况——
有几个 DLL 里只有位图或光标。被跳过的文件保持原始英文内容。

## 校验报告了问题

**控件越过右边界**

被加宽的控件放不进对话框了。对话框仍可使用，但标签可能被截断。
请带上日志中的对话框名称反馈。

**某个 DLL 加载失败**

该文件已不可用，请不要安装这个语言包。重新构建；
若同一文件再次失败，请带上文件名和构建号提交 issue。

## 安装之后

**SOLIDWORKS 仍然只显示英文**

- 没有重启 SOLIDWORKS。
- 装错了文件夹。用 `swbilingual-cli.py locate` 确认被替换的正是当前运行的
  SOLIDWORKS 所属的那个文件夹，同时确认工具没有报权限错误。
- SOLIDWORKS 当前语言不是英文，加载的是别的语言包。
  要么把界面语言切回英文，要么针对你实际使用的语言重新构建双语包。

**SOLIDWORKS 打不开，或菜单是空的**

还原备份后重启：

```
python swbilingual-cli.py restore "C:\...\lang\english.backup-20260824-153000" "C:\...\lang\english"
```

备份文件夹就在语言文件夹旁边，名称带有安装时刻的时间戳。

**安全软件报告某个 DLL 有问题**

改写资源会使每个被修补文件的数字签名失效，因此签名校验现在会失败，这是预期结果。
若安全软件隔离了文件，请先还原备份，然后要么添加信任例外，要么不使用双语包。

**某个标签读起来别扭，或出现一对空括号**

少数中文标签把键盘快捷键写在括号里，标记被移除后括号留了下来，例如 `从组中移除()`。
在参考构建上，这种情况占 25,033 条合并条目中的 16 条。
如果它在日常使用中确实碍事，欢迎反馈该标签。

## SOLIDWORKS 升级后

升级会替换语言包。用新的英文包和中文包重新构建一次，再照常安装即可。
确认新包可用后，旧备份可以删除。

## 如何求助

提交 issue 时请附上构建号、失败的步骤，以及日志
（桌面程序里有**保存日志**按钮）。请不要附带语言包文件。
