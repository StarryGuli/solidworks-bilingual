# 工作原理

SOLIDWORKS 从当前语言对应的语言包文件夹读取界面文字。英文包大约有 270 个文件，
其中 60 个是资源 DLL，另有两个 XAML 字典。里面没有任何加密或混淆：
文字就存放在普通的 Win32 资源里。

本工具先复制一份英文包，再改写副本中的文字，
让每个短标签后面跟上同构建号中文包里对应的中文标签。
SOLIDWORKS 依旧加载英文包，察觉不到任何变化。

## 为什么构建号必须一致

资源是按数字 ID 寻址的，不是按文字。`sldresu.dll` 里的字符串 ID 4711
指的是该构建分配给它的那一条。构建变化时 ID 会重新分配，
因此把 A 构建的 4711 和 B 构建的 4711 配成一对，得到的是一本正经的胡说：
某个命令被配上了另一个毫不相干命令的中文。

工具会读取两侧 `sldresu.dll` 的文件版本，不一致就拒绝继续。
版本号直接从 PE 头解析，因此这项检查在没装 SOLIDWORKS 的机器上同样有效。

## 第 1 步 —— 字符串表

界面文字大部分存放在 `RT_STRING` 资源中。Windows 把它们按 16 条一组分块存储，
每条字符串前有一个以 UTF-16 码元计的长度前缀。

工具逐个 DLL 读取英文块和中文块，按块 ID 配对，改写通过合并规则的条目。
中文包里没有的块保持原样。

中文包有时会给资源标上不同的语言 ID，因此中文侧只按块 ID 索引；
写回时使用**英文包原有的**语言 ID，这才是 SOLIDWORKS 查找时用的那个。

### 两段式条目

MFC 把工具栏命令存成一条带换行的字符串，分为两段：

```
Extrudes a sketch or selected sketch contours in one or two directions.\n拉伸凸台/基体
```

第一段是状态栏说明，第二段是命令名。两段分别按合并规则判断。
实际情况是说明通常超过 60 字符上限而保持英文，命令名则变成双语。
段数多于两段的是注册用数据块（文件类型关联、ProgID 等），一律不动。

## 第 2 步 —— 对话框模板

对话框自带文字：窗口标题、每个按钮和静态标签的文本，都在 `DIALOGEX` 模板内部，
第一步的字符串表处理完全看不到它们。

模板是一段紧凑的二进制结构。工具把它解析成头部、可选字体块和控件列表，
再重新构建一遍，与原始字节逐字节比对。**若重建结果与原文不完全一致，该模板直接跳过。**
这是防止把没读懂的结构以损坏形式写回去的关键保险。

能通过往返测试的模板，还要与中文侧模板核对：控件数量、每个控件的 ID 和类别都必须一致。
之后才合并按钮和静态文本的标题。

### 加宽控件

双语标题比英文标题长，可能被截断。合并标题后，工具按对话框单位估算新宽度
（拉丁字符约 4，汉字约 8），把控件按差值加宽，但**只向空白处扩张**：
遇到同一行范围内任何控件的左边界就停，遇到对话框边界也停。
位于该控件内部的控件（例如分组框）不阻挡扩张。

工具不移动任何控件，也不改变对话框尺寸。实在没有空间时，标题照常合并、控件保持原宽，
这与语言包原本处理过长英文时的截断行为一致。

## 第 3 步 —— XAML 字典

PropertyManager（SOLIDWORKS 窗口左侧那个面板）的文字来自
`DveDictionary.xaml` 和 `pmdictionary.xaml`，它们是普通的 XML 资源字典：

```xml
<sys:String x:Key="IDS_FILLET_TITLE">Fillet</sys:String>
```

条目按 key 配对，套用同一套合并规则。key 中含 `NoTranslation` 的条目，
以及任何含转义标记的条目，都会跳过。
被替换文本以外的部分，英文文件的编码和换行符逐字节保留。

## 三项检查

校验会把成品与英文原包对照：

1. **资源清单。** 原包中出现过的每一种资源类型，在修补后的文件里都必须仍然存在，
   且条目数不少于原来。这能抓住资源更新部分失败的情况——
   否则这种故障要等 SOLIDWORKS 弹出一个空菜单时才会被发现。
2. **对话框布局。** 每个被修改的对话框都重新解析，控件与原件逐一比对。
   新产生重叠、或越过对话框边界的控件都会被报告。
   向空白处加宽的控件只计数，不算问题。
3. **加载测试。** 每个被修补的 DLL 都用真正的 Windows 加载器加载一次，
   而不是当作数据文件打开。资源目录结构非法的文件会在这一步暴露。

这三项检查也有独立脚本版本 —— `src/verify.py`、`src/layout_audit.py`、
`src/loadtest.py` —— 接收目录参数并打印报告。

## 诊断脚本

| 脚本 | 用途 |
|---|---|
| `src/analyze_skips.py EN.dll CN.dll` | 统计每条字符串被跳过的原因。某个本以为会合并的标签没变时用它 |
| `src/find_term.py EN.dll CN.dll Fillet` | 显示含某词条目的中英原文及合并判定 |
| `src/check_terms.py patched.dll` | 在成品文件中抽查一组常用命令名 |
| `src/dlg_dryrun.py EN_dir CN_dir` | 报告有多少对话框模板能干净往返，以及会改动什么 |
| `src/probe_types.py X.dll` | 列出文件中的资源类型及各自条目数 |

日常场景用 `preview` 命令即可覆盖上述大部分需求，且在任意操作系统上都能运行。
